# Observations — 2026-07

## AAR: the OPM-1.G gate loop (research-foundry operator-mcp P1)

> **Primary lesson (one line):** move mutation verification INTO the fix step — a remediation is not
> submitted until each fix has been reverted in place and shown to break a NAMED test. Rounds 4 and 5
> of this gate exist almost entirely because closure was asserted rather than demonstrated.

**Context.** P1 of `research-foundry-operator-mcp` is 4 of 29 story points: a contract-freeze phase
(schemas + identity + confirmation policy, no transport, no production caller). It consumed **five
security-review rounds and ~2.4M+ tokens**. The gate was not malfunctioning — it found genuine defects
every single round, including two real privilege escalations. The *loop shape* malfunctioned.

### The core finding: closure was asserted, not demonstrated

Each round fixed real findings and **asserted** closure. The next round discovered the closure evidence
was hollow, and generated a fresh finding set *from the remediation itself*.

The proof case is BLOCK-4. NEW-19 (audit-health latch) was fixed correctly in code, and shipped with
four purpose-built tests. All four **passed when the fix was reverted**: their fake `health_check`
never persisted a row, so the reverted code path never engaged and the tests re-entered the fake every
time — accidentally reproducing the very behaviour they asserted. A fully green suite proved nothing.
The regression was caught only incidentally, by an unrelated test.

**Rule to encode:** a remediation is not submitted until each fix has been **reverted in place, shown
to break a NAMED test, and restored**. Move mutation verification into the FIX step, not the next
REVIEW round. Rounds 4 and 5 exist largely because this was not done — collapsing them into round 3
was available the whole time.

### Secondary recurring shapes (each produced findings in multiple rounds)

1. **Fix the sibling, not just the finding.** Fixing one schema field and leaving the structurally
   identical field beside it produced findings in *every* round it was examined:
   `terminal_receipt.denial_reason_code` closed → `action_receipt.reason_code` still open (BLOCK-2);
   `audit_delivery.detail` closed → `audit_delivery.audit_event_id` still open (R5-BLOCK-1); the
   `if/then` presence coupling applied to one `$def` only (BLOCK-3 → R5-BLOCK-3).
   **Rule:** once a file yields findings in 2+ rounds, stop finding-driven editing and do a systematic
   per-container × per-property sweep with an explicit matrix.

2. **False authoritativeness — repeatedly introduced BY the fix that closed the prior finding.**
   Comments, docstrings and schema `description`s asserting properties the code does not have. Three
   round-3 findings and two round-4 findings were this class. Worst instance: a docstring claiming a
   caller passing `str(exc)` "cannot land unredacted text in a receipt" when the redaction stripped
   only marker keywords and left absolute paths verbatim — *written while fixing the finding about
   unredacted text*. A "provable no-op" claim about a barrier-file write was also false (regex-equivalent
   but not identical patterns changed match multiplicity) and was propagated into a closure section
   before being caught.
   **Rule:** every prose claim must be checked against shipped code, especially prose written *by* a fix.

3. **Fix the layer below.** Hardening a symbol while its delegate still offers the unsafe path:
   `authorize_operation` hardened while `verify_confirmation` still reported a replay as accepted;
   the serve-extra import fixed while `resolve_operator_identity` still *constructed* the serve-gated
   class at runtime (clean import, failure on first real use).

4. **Reviewer lenses are not fungible.** The validator cleared a critical authorization bypass twice;
   the security lens found every real defect. A cheap Sonnet pre-sweep (~30k tokens) independently
   found the highest-severity item of its round — cheap breadth before expensive depth is worth it.

5. **Green tests are not evidence; a passing suite is a floor, not a signal.** Every round had a green
   targeted suite. The defects were found by mutation, adversarial probing, and reading prose against code.

### What worked

- Running the cheap sweep and the expensive lens as **independent lenses** — they converged on three
  findings, which raised confidence in both.
- **Orchestrator-side empirical re-verification** rather than accepting subagent reports: an agent's
  "all layers implemented" report was contradicted by a 4-line probe showing the runtime path still
  failed.
- **Exhaustive-map-plus-import-time-check** instead of a permissive default: replacing a two-way
  read/mutate role split with a per-kind map that raises at import if a kind is unclassified converts a
  future fail-open into a loud startup failure.
- **Inverting tests that pinned unsafe behaviour** rather than weakening fixes to match them (two cases:
  `viewer` reading job status; audit health "must deny without re-probing").

### Process cost note

Blocking-finding counts by round: 6 → 13 → 6 → 9 → 4. Converging, but the tail is expensive because
each remediation seeds the next round. The single highest-leverage change is item 1 above.
