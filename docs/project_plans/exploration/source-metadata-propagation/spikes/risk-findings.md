## Deal-Killer Assessment

**Charter deal-killer** (verbatim): *"If propagating source attributes to claims cannot be made deterministic and fully recomputable from files alone — i.e. it requires a model call on the read path, or makes the derived catalog DB authoritative — abandon."*

**Not confirmed by this leg — this is properly the tech leg's question, and nothing found here contradicts feasibility.** Everything this risk leg touched (schema additivity, verify's non-participation in the source_card schema, the pediatric_cds hard-gate) is orthogonal to whether propagation itself requires a read-path model call. No evidence found that capturing static metadata (DOI, authors, publisher) or caching a third-party rating with its own `observed_at` requires anything but a write-time fetch + deterministic carry-through at claim-map time — consistent with the existing `_term_index` write-time precedent cited in the charter. **Refuted-by-default at this leg's evidence, pending tech leg confirmation.**

### Additional deal-killer surfaced by this leg (not in the charter's frontmatter)

**A rating/count that is querced-as-current but was captured at ingest time and never refreshed is not "recomputable from files alone" in the sense the charter's own principle demands — it's recomputable but wrong.** The charter's deal-killer is about *mechanism* (no model call, no authoritative DB); it doesn't cover *correctness-over-time* of a cached fact. This leg proposes treating this as a **conditional-go gate**, not a literal deal-killer: ship third-party assertions only with a mandatory `observed_at` timestamp and an explicit non-authoritative framing (never silently overwritten — a refresh is a new assertion, not a mutation), mirroring the `source_assertion.schema.yaml` `observed_at` field (`:78`) already established for the Reusable Assertion Ledger.

## Third-Party Terms — Caching + Redistribution in a Published Bundle

**Claim status per row.** Rows marked **Live-verified 2026-08-06** are `supported` — each quotation is
traceable to a dated retrieval recorded in
[`def-6-tos-verification-2026-08-06.md`](./def-6-tos-verification-2026-08-06.md) (source ids S1–S5,
N1–N4). Rows *without* that marker remain `inference` from general domain knowledge of these
programs' public policies and have **not** been re-verified against live pages — DEF-6's scope was
Semantic Scholar and NCBI only. The "Redistribute?" column is `inference` throughout: it is this
leg's reading of the terms, **not legal advice**, and no row of it closes a clearance gate.

| Source | License / Terms | Cache? | Redistribute inside an evidence bundle? |
|---|---|---|---|
| **Crossref** (REST API metadata) | Metadata dedicated to the public domain — Crossref publishes its metadata under **CC0**. | Yes | Yes — CC0 imposes no attribution/share-alike constraint. |
| **OpenAlex** | **CC0** (explicit public-domain dedication; OpenAlex's stated purpose is downstream reuse). | Yes | Yes. |
| **DataCite** (DOI metadata) | **CC0** for the metadata record itself. | Yes | Yes. |
| **Semantic Scholar Academic Graph (S2AG) API** | ⚠️ **Live-verified 2026-08-06 — no blanket license exists.** The S2 API License Agreement defers per-dataset: use of S2 Data is "separately governed by the licenses that accompany such S2 Data, such as **CC BY-NC or ODC-BY**". ODC-BY is one possibility, not the governing license, and **CC BY-NC (NonCommercial) is live**. No public page maps dataset → license. Separate affirmative duty: "Licensee will include an attribution to 'Semantic Scholar'…". The "repackage, sell, … or sublicense" prohibition binds the **API**, not derived data. | Yes | ⚠️ **Not assertable in advance.** Depends on the license accompanying the specific payload; must be captured per record in `license_basis` at acquisition. A hardcoded `ODC-BY` default would be a false assertion of fact. |
| **PubMed / NCBI E-utilities** — *bibliographic fields* (PMID, title, authors, dates) | **Live-verified 2026-08-06.** Not a license at all: US-government-created content "is within the public domain" and "not subject to copyright protection in the United States" — a wider grant than CC0/ODC-BY. Attribution **requested, not required** ("Courtesy of the National Library of Medicine"). Rate limits: **3 req/s without an API key, up to 10 req/s with one**; `tool` + `email` identify the caller. | Yes | Yes — unencumbered. |
| **PubMed / NCBI E-utilities** — *abstracts and quoted passages* | **Live-verified 2026-08-06 — this is the actual constraint.** Abstracts "may incorporate material that may be protected by U.S. and foreign copyright laws"; reproduction beyond fair use "requires written permission of the copyright owners". PMC, Bookshelf, OMIM, PubChem carry third-party copyright. The encumbrance is **upstream publisher copyright, not NCBI policy** — NCBI disclaims authority to grant permission on submitters' behalf. | Yes | Fair use or written permission. **This — not a bulk-scraping rule — is what limits RF**, because the payload RF redistributes is usually the abstract/passage, not the skeleton. |
| **PubMed / NCBI** — *bulk-downloaded data* (NLM download site) | **Live-verified 2026-08-06.** Redistribution permitted subject to four affirmative duties: (1) maintain most-current data **or** "make known in a clear and conspicuous manner" that it is not current; (2) "acknowledge NLM as the source … 'Courtesy of the U.S. National Library of Medicine'" (**required** here, unlike general content); (3) do not imply NLM endorsement; (4) no fees paid to NLM. | Yes | Yes, under all four duties. Duty (1) makes staleness disclosure a **term of use**, not just an internal correctness property — see §Staleness Invariant. |
| **Scopus / Web of Science (Clarivate) / journal-ranking vendors (e.g. JCR Impact Factor, SCImago)** | **Proprietary, contractual.** Subscription/API terms explicitly prohibit caching and redistributing derived data (rankings, impact factors, citation counts) in a third-party product absent a paid data-license agreement. | **No** (without a separate license) | **No** — this is the concrete deal-killer-shaped risk for any "citation rank"/"journal impact factor" feature: it cannot ship using these vendors' data without procurement, and RF has no existing licensing relationship. |

**Concrete conclusion** *(revised 2026-08-06 after DEF-6 live verification; `inference`)*: DOI-registry
metadata (Crossref/OpenAlex/DataCite) is believed unconditionally safe to cache and redistribute —
`inference`, not re-verified. **Semantic Scholar is *not* safe on attribution alone**: the prior
version of this line said it was, and the live license agreement contradicts it — the license is
per-dataset and may be CC BY-NC, so redistribution scope cannot be asserted before the payload's own
license is read, and `license_basis` must carry it per record. **NCBI splits by field, not by
source**: bibliographic fields are public domain and unencumbered; abstracts and quoted passages
carry upstream publisher copyright and need fair use or written permission; bulk-downloaded data is
redistributable under NLM's four affirmative duties, of which conspicuous staleness disclosure is
one. The prior version's "NCBI disallows bulk redistribution as a substitute product" was
**unsupported by any live page** and has been struck. Scopus/Web of Science/commercial
journal-ranking data remains **out of scope for v1** absent a procured license (`inference`;
DEF-2 blocks acquisition, not merely redistribution) — recommend explicitly excluding these vendors
from the initial third-party-assertion source list rather than leaving it ambiguous.

## Staleness Invariant

A citation count, ranking, or backlink count is a **point-in-time observation**, never a current fact. The existing `source_assertion.schema.yaml` `observed_at` field (`:78`, required alongside `extractor`/`schema_version`, `:64`) is the correct precedent to reuse verbatim: every third-party assertion must carry its own `observed_at` timestamp **distinct from** the source card's `accessed_at` (which is about the source, not the assertion-about-the-source). The honesty invariant: **a refresh creates a new assertion record with a new `observed_at`; it never overwrites the old one in place.** Any report/claim surfacing the value must render it as "N citations as of `observed_at`", never as a bare number. This closes the "true only at retrieval time" gap named in the charter without inventing new machinery — it's the Reusable Assertion Ledger's own pattern, applied to itself.

## Governance Hazard — Agent-Writable Rating Reading as RF-Attested

Traced `_RIGHTS_GOVERNED_FIELDS` (`governance.py:35-40`): exactly 4 named fields — `rights_record.overall_status`, `content_reuse_assessment.decision.status`, `rights_extension.clearance_status`, `synthesis.attestation.status`. The `no_agent_cleared_rights_value` guard (`:500-520`) is a **field-name allowlist check**, not a pattern/heuristic check on values shaped like `CLEARED_*`/`attested` appearing anywhere. **A brand-new field — e.g. `trust.third_party_rating` or `attribution.citation_rank` — is invisible to this guard by construction**; nothing stops an agent-writable ingest path from writing a value there that a downstream reader could plausibly mistake for an RF-authored/attested judgment (the exact hazard the charter names, and the exact class of gap `adr-rights-entity-model.md` §9.10 already documents once — "guarded only one of two enum write paths"). **Mitigation, concrete**: (1) never name a new field with a bare `status`/`rank` suffix that could alias the governed vocabulary; (2) every third-party assertion field must carry its own `source: "crossref"|"semantic_scholar"|...` + `observed_at` co-located with the value so it is structurally impossible to render without provenance; (3) add the new field(s) to `_RIGHTS_GOVERNED_FIELDS`-adjacent documentation (not necessarily the enum-value guard itself, since third-party ratings aren't a `CLEARED_*`/`attested` enum) as an explicit "third-party, not RF-attested" callout in the schema's own `description:` — this repo's existing convention (see `pediatric_cds.schema.json`'s own extensive inline `$comment`/`description` scoping) is to document this boundary in the schema artifact itself, not rely solely on a runtime guard.

## Concrete Migration Path

1. Add new fields exclusively under `source.*` (e.g. `source.identifiers.{doi,pmid,isbn}`, `source.citations_backlinks`) and a new top-level `third_party_assertions[]` array on `source_card` — both land in already-`additionalProperties: true` territory; zero schema-version bump required for `source_card.schema.yaml` itself (bump the doc's own informal version comment for changelog hygiene only).
2. Explicitly exclude the `pediatric_cds` namespace from this change — enforce via a fast unit test that asserts the new writer never emits `pediatric_cds.<new_key>`.
3. Each `third_party_assertions[]` entry requires `{source, value, observed_at, license_basis}` at minimum — `license_basis` records which row of the licensing table above justified caching it (audit trail for a future ToS dispute).
4. No backfill of existing cards. Ship the tri-state coverage signal (row above) in whatever query/filter surface consumes the new attribute from day one — this is a hard precondition of "go," not a follow-up.
5. Before merge: run a real `rf verify` against one of the 7 pediatric bundles pre- and post-change (not done in this leg — no execution environment invoked) to convert the code-trace claims above into an empirical CI gate. Recommend this as an explicit acceptance criterion on the eventual Feature Contract/plan, not left implicit.
6. Do not add Scopus/Web of Science/journal-ranking-vendor data sources in v1; gate behind a named licensing-procurement precondition if ever requested (mirrors the charter's own "conditional" framing for third-party ingestion generally).
