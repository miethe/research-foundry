# Source Metadata Propagation — Prior-Art Findings

## 1. External Standards Match Table

| Standard | What it solves | Fit for RF's problem | Verdict |
|---|---|---|---|
| **W3C PROV-O** ([TR/prov-o](https://www.w3.org/TR/prov-o/)) | General-purpose provenance ontology. `prov:wasAttributedTo` links an Entity to an Agent (§4.1, Property 6: "Attribution is the ascribing of an entity to an agent"). The **qualification pattern** (§3.3) reifies a binary relation into its own node — `prov:qualifiedAttribution` → a `prov:Attribution` instance carrying `prov:agent` + `prov:hadRole`, so arbitrary extra properties (time, role, basis) can be hung off the *relation itself* rather than the entity or the agent. | Directly answers "rating asserted by X" — the qualified-relation pattern is exactly the shape needed to say "source S was rated 4/5 by Semantic Scholar's TLDR model on date D under role reviewer" without polluting S's own record. But PROV-O is a graph ontology (RDF/OWL) with no native concept of "third-party assertion with retrieval terms/license" — it models *who* and *when*, not *under what reuse terms*. Also heavier machinery (full RDF graph + qualification reification) than RF's flat YAML files need. | **Adapt** — steal the qualified-relation *shape* (assertion node separate from subject, carrying agent/time/role), not the RDF serialization. |
| **W3C Web Annotation Data Model** ([TR/annotation-model](https://www.w3.org/TR/annotation-model/)) | Models a first-class Annotation resource with `body`, `target`, `creator`, `created`/`generated`/`modified` (§3.3.1) whose `target` is always an "External Web Resource" (§3.2) — independently addressable, dereferenced separately. Spec explicitly warns embedded target metadata is "hints... not to be considered authoritative." | **Closest structural match of the six.** RF's problem is precisely "an annotation ABOUT another document, carrying its own creator/created, where the annotated document's own metadata is untouched and the annotation's copy is explicitly non-authoritative." This is *the same shape* RF's `rights_summary` mirror already uses (`mirror_is_authoritative: const false`) — Web Annotation gives that same pattern a name and a precedent one layer up: a full assertion-about-a-source object, not just a rights mirror. | **Adopt the pattern, not the vocabulary.** Model a third-party-assertion-about-source object with `creator`/`created`/`target` fields; skip JSON-LD/IRI machinery. |
| **Nanopublications** ([Kuhn et al., Sci Data 1, 2014, doi:10.1038/sdata.2014.36](https://doi.org/10.1038/sdata.2014.36); overview: [Wikipedia](https://en.wikipedia.org/wiki/Nanopublication)) | Splits any RDF statement into three named graphs: **assertion** (the claim itself), **provenance** (how the assertion was derived/created), **publication info** (who published it, when, under what identifier). Explicitly designed so "provenance and publication information eases authorship recognition, credit distribution, and citation" independent of the assertion's truth. | Directly relevant to the charter's core ask: separating a claim ("source X has rating 4.2") from who vouches for it (provenance graph) from who published/retrieved it (pubinfo graph). RF's `source_assertion.schema.yaml` already has an analogous three-way split: `assertion_text`/`identity` (the assertion), `extraction_provenance` (who/when extracted), and the top-level `assertion_id`/lifecycle (publication-like identity). The nanopub triple-graph split is a good **mental model** but its unit of publication (a whole RDF nanopub, independently citable/versioned) is heavier-weight than one field on a source card. | **Adapt** — RF's existing `source_assertion` shape is already a nanopub-flavored split; extending its `extraction_provenance` block (or a sibling block) to third-party assertions-about-sources is the low-friction move, not adopting nanopub tooling. |
| **RO-Crate** ([spec v1.1](https://www.researchobject.org/ro-crate/specification/1.1/)) | Packages a research object's data files + metadata + provenance into one portable bundle via a root `ro-crate-metadata.json` (JSON-LD), with dedicated sections for agents, licenses, and `CreateAction`/provenance of entities. | Relevant to *bundle shape*, not assertion modeling — RF's evidence bundle (source cards + claim ledger + report, exported as a directory) is already structurally an RO-Crate-like artifact (portable dir + machine-readable manifest + license/agent metadata). Doesn't solve the "assertion about a source" problem at all; it's a packaging convention for what ships in the bundle. | **Ignore for the assertion-modeling question; loosely adopted already** for bundle packaging (RF's evidence bundle + `run.json` manifest is the RO-Crate-equivalent artifact) — no new work indicated by this exploration. |
| **DataCite / Crossref / OpenAlex / Semantic Scholar** | Live metadata + citation-graph APIs. Field names actually seen: Crossref Works — `DOI`, `is-referenced-by-count`, `reference-count`, `license` (array of `{URL, start, content-version, delay-in-days}`), `container-title`; DataCite Metadata Schema 4.x — `Identifier`, `Creator`, `Contributor`, `RelatedIdentifier` + `relationType` (`IsCitedBy`/`Cites`), `Rights`/`RightsList`; OpenAlex Work object — `cited_by_count`, `doi`, `ids.pmid`/`ids.mag`, `open_access.oa_status`/`oa_url`, per-`location.license`; Semantic Scholar Graph API exposes `citationCount`, `influentialCitationCount`, `externalIds.{DOI,PubMed,ArXiv}`, `openAccessPdf.{url,status}`. | This is the **field-name source of truth** for what "rich source metadata" actually looks like: `DOI`/`externalIds.PubMed` for identity, `is-referenced-by-count`/`cited_by_count`/`citationCount` for the "backlinks" the charter asks for, `license`/`RightsList`/`open_access.oa_status` for the terms field. Every one of these fields is a **third-party assertion with its own provenance** (the API's snapshot date, the aggregator's own attribution) — exactly the category the charter is worried about being mistaken for RF-authored fact. None of these APIs model "assertion about a source" as a first-class entity with attribution — they treat the citation count as their own current fact, snapshot-dated by the fetch, not qualified by "asserted by Crossref as of query-time." | **Adopt field names, not the modeling pattern.** Use `is-referenced-by-count`/`cited_by_count` and `DOI`/`RightsList` shapes as the concrete attributes to capture; wrap each in RF's own attribution wrapper (who fetched it, when, from which API, under what API ToS) rather than trusting the aggregator's implicit "current fact" framing. |
| **SPDX attribution** ([spec v2.3, Package Information](https://spdx.github.io/spdx-spec/v2.3/package-information/)) | Separate license fields for different *epistemic status*: `PackageLicenseDeclared` (what the author says), `PackageLicenseConcluded` (what the SPDX document creator concluded after review — explicitly allows `NOASSERTION`), `PackageCopyrightText`, `PackageAttributionText` (free-form, cardinality 0..*, "acknowledgements that might be required to be communicated"). The declared/concluded split is the direct precedent for "don't conflate what the source claims about itself with what a third party has determined." | This is the best precedent for RF's licensing/terms field specifically — SPDX's declared-vs-concluded split maps cleanly onto RF's rights model: `rights_record` (RF's own concluded determination) vs. a hypothetical `PackageLicenseDeclared`-equivalent (what the source itself states) vs. a third-party rating (Semantic Scholar's `openAccessPdf.status`, e.g.). The `NOASSERTION` sentinel is the same shape as RF's existing `unknown` enum members throughout `rights_record`/`rights_summary`. | **Adopt the declared/concluded/NOASSERTION vocabulary as a naming pattern** for any new terms-of-reuse field on third-party metadata — RF already has the equivalent enum shape (`unknown` defaults), so this validates the existing convention rather than requiring new work. |

**Reference-manager / systematic-review precedent**: Zotero's item model has no first-class "third-party quality rating" entity — ratings/tags are free-text or plugin-specific, not schema-governed. Covidence's public docs (fetched) don't expose the technical data model for risk-of-bias assessments; from established systematic-review methodology (Cochrane Handbook RoB2, GRADE), the field convention is: assessor identity + tool name + assessment date + per-domain judgment, kept as a **separate record referencing the study**, never merged into the study's own bibliographic record — the same separate-entity precedent as PROV-O's qualified attribution and Web Annotation's target-external-resource pattern. No new tooling insight beyond what PROV-O/Web-Annotation already supply; not independently actionable.

## 2. Internal Matches

| Internal artifact | Similarity to the ask | Delta |
|---|---|---|
| **`schemas/source_assertion.schema.yaml`** (Reusable Assertion Ledger) | Very high. Already models: an assertion (`assertion_text`, `identity` fingerprint) with its own **provenance block** (`extraction_provenance`: `extractor`, `provider`, `model`, `observed_at`) — structurally identical to nanopub's assertion/provenance split. Already carries a **non-authoritative mirror pattern** (`rights_summary`, `mirror_is_authoritative: const false`) — structurally identical to Web Annotation's "hints, not authoritative" warning. Already has a **qualified-relation-like extension point** in `synthesis.input_refs[]` (`source_assertion_id` + `contribution` enum: anchor/corroborating/contradicting/scope_limiting) — this is PROV-O's qualified-influence shape in miniature, already landed. | Missing: (a) no `evidence_item_type`/`judgment_basis` value for "third-party quality signal" (the 8-member enum in `extensions.evidence_taxonomy` covers `bibliographic_metadata` but not an explicit "third-party rating/citation-count" category — closest fit is `other` or an additive enum member); (b) no `asserted_by`/agent-identity field distinct from `extraction_provenance.extractor` (which is RF's own extraction tooling identity, not a third party like Semantic Scholar); (c) no retrieval-terms/license field analogous to `rights_summary` but scoped to the *third-party API's* ToS rather than the *source content's* rights. |
| **`docs/dev/architecture/adr-rights-entity-model.md`** (landed `17a2cb0`) | Very high — this IS the separate-governance-entity precedent named in the charter. Establishes the exact decision the tech leg needs to make: denormalized non-authoritative mirror (`rights_summary`) attached to the evidence entity, vs. a deferred runtime-resolution API (rejected for the same files-canonical/no-model-on-read-path reason this charter's deal-killer names). Also establishes the fail-closed authorization boundary pattern (`CLEARED_*`/`counsel_approved` human-only, proven by negative tests) — directly reusable for "a rating must never be mistaken for RF-attested fact." | This ADR's mirror pattern was built for *rights*, a single well-defined axis with 5 backing schemas. A third-party-assertion entity is more open-ended (arbitrary third-party APIs, not one canonical schema) — the ADR doesn't itself resolve whether an open-ended third-party-metadata mirror needs the same 5-schema authoritative-record backing, or can be lighter (a single generic `third_party_assertion` block, closer to `source_assertion`'s existing shape). |
| **`_term_index` write-time derivation** (landed `d71a261`, `services/term_index.py` / `term_index_backfill.py`) | High, as a **propagation mechanism precedent**, not an entity-modeling one. Demonstrates RF's established pattern for "compute once at write time, store on the claim, never require a read-path recompute": deterministic extraction writes `claim["_term_index"]`, is additive-only (never overwrites an existing key), and ships with a **non-clobbering backfill** for pre-existing ledgers (`backfill_term_index`, `claim.get("_term_index") is None` check). | This is the concrete deterministic-propagation-to-claims pattern the tech leg should reuse for attribute propagation (e.g. `claim["_source_attributes_index"]` computed at claim-map write time from cited source cards' `rights_summary`/`trust`/new third-party block) — but `_term_index` propagates *derived vocabulary*, a single flat structure; propagating N cited sources' heterogeneous attributes (rank, rating, license) up to one claim needs an aggregation-semantics decision (min/max/set) that `_term_index` didn't have to make (it has one producer, not N conflicting sources). |
| **`services/catalog_service.py`** (derived SQLite+FTS5 read model) | Medium — this is the sanctioned pattern for *where* filtering/sorting on propagated attributes could live: a rebuildable, non-canonical derived index (`PRAGMA user_version` bump on schema change triggers drop+recreate, never a silent partial migration), imported via the export layer (`export_run()`), never by parsing files directly, with sensitivity gating enforced at read time. | Confirms the catalog is the natural home for **query-time** filtering by propagated source attributes (rank/rating/license), but the catalog derives from `export_run()`'s already-flattened claim graph — so propagation to claims/`_term_index`-style write-time indexing must happen *before* catalog import, not inside the catalog layer itself. The catalog can't be where propagation logic lives; it can only be where the propagated result becomes filterable. |

## 3. Recommended H5 Estimation Anchor

**Anchor: the landed `rights-entity-model-v1` feature (ADR `docs/dev/architecture/adr-rights-entity-model.md`, merged `17a2cb0`).**

Justification: it is the closest prior RF feature by every dimension that matters for sizing this one —
(a) it added a **new denormalized, non-authoritative mirror block** to the same two entities (`source_card`, `source_assertion`) this exploration would touch; (b) it had to solve the identical **files-canonical / no-read-path-model-call** constraint (resolved via mirror-not-runtime-API, the same resolution this charter's deal-killer anticipates); (c) it required an **additive, no-backfill-required schema change** at capture time plus an optional backfill migration for pre-existing cards — the same shape as propagating third-party metadata onto existing pediatric-CDS bundles; (d) it had a **fail-closed governance boundary** (agent-writable paths can never mint an authoritative-looking value) that generalizes directly to "an agent-fetched third-party rating must never read as RF-attested." It shipped across 6 phases (P0–P5) with two independent negative-test suites as the completion gate. A source-metadata-propagation feature that is schema-additive + mirror-pattern + fail-closed-governance is very close in shape and should anchor to a similar phase count and gate structure — not to a smaller precedent like `_term_index` (single-producer, no governance axis) or the Knowledge MCP (a new read-only service layer, a different risk profile).

## 4. Build-vs-Adopt Recommendation

**Build on RF's own vocabulary — extend `source_assertion.schema.yaml`, do not adopt an external ontology wholesale.**

None of the six external standards is directly embeddable without translation: PROV-O and nanopublications are RDF-native and would require a parallel serialization RF doesn't otherwise use; Web Annotation is JSON-LD-oriented; RO-Crate is a packaging convention already informally satisfied by RF's evidence-bundle export. What RF should adopt is **shape, not vocabulary**, from three of the six:

1. From **Web Annotation** and **nanopublications**: the discipline of keeping a third-party assertion's own `creator`/`created` (or `extraction_provenance`-equivalent) fields distinct from, and never overwriting, the target source's own metadata — RF's `source_assertion.schema.yaml` already does this for RF-authored extraction; extend the same `extraction_provenance`-sibling pattern to third-party assertions, with a field that names the *external* agent (e.g. `asserted_by: {type: third_party_api, name: "semanticscholar", ...}`) distinct from RF's own `extractor`.
2. From **PROV-O**'s qualified-relation pattern and the **rights-entity-model ADR**'s mirror precedent: a new sibling block on `source_assertion` (or `source_card`) — call it e.g. `third_party_assertions[]` — following the exact `rights_summary` shape: `mirror_is_authoritative: const false`, an array of `{asserted_by, asserted_at, retrieved_at, value, terms_of_reuse, source_api}` entries, never conflated with RF's own `judgment_basis`/`evidence_item_type` axis (§9.1's independent-axes rule applies again here).
3. From **SPDX**'s declared/concluded split: keep the third-party value and RF's own governance judgment about it in visibly separate fields (a rating is `declared`-equivalent — what the third party asserts — never automatically promoted to `concluded`/attested).
4. From **DataCite/Crossref/OpenAlex/Semantic Scholar** field naming: use their field names as the concrete attribute vocabulary to capture (`cited_by_count`/`is-referenced-by-count`, `DOI`, `RightsList`), not their APIs' framing of these as current, unqualified facts.

Propagation to claims should reuse the **`_term_index` write-time derivation pattern**: compute a deterministic summary at claim-map write time (or at a well-defined write point before catalog import), additive-only, non-clobbering, backfillable — with an explicit, named aggregation rule (the tech leg's open question: min/max/set-union across N cited sources) rather than an implicit "first source wins."

This keeps the deal-killer refuted: no read-path model call, no authoritative derived DB — the mirror + write-time-index pattern is 100% file-recomputable, matching every precedent found.
